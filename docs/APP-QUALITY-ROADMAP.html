Product Quality Roadmap

A practical plan for English Automaticity, DeutschFlow, Study Tracker, Settings, PDF Studio, and Conversation Studio—viewed through the needs of a teacher, learner, and product manager.

Evidence boundary. Runtime, build, test, and deployment findings are confirmed. The experience findings below are prioritised hypotheses based on the reported screens and flows; keyboard, screen-reader, and learner-observation sessions are still required before claiming accessibility or learning-outcome compliance.

1. Product critique by role

Teacher perspective

Teach, observe, intervene

P0“Completed” must distinguish attempted work from checked mastery. A teacher needs the evidence, correction, and next intervention—not only a progress percentage.
P1Generated starter material must be visibly labelled as original draft content, editable before assignment, and attributable to a level, skill, and learning goal.
P1Long catalogues need compact filters, a searchable multi-select, and saved class views. A teacher should not scroll through 72 units to prepare one lesson.
Learner perspective

Know what to do next

P0Every practice card needs a stable layout at narrow widths: status, title, time, and “Open practice” must remain inside the card and touch-friendly.
P0Back navigation must return to the prior learning context with the selected unit, filter, scroll position, and unsaved safe draft preserved.
P1Show one clear reason for the next task: an error to repair, a due review, or a new goal. Avoid presenting seven equal choices without guidance.
Product manager perspective

Reliable delivery, clear ownership

P0Production readiness needs a repeatable gate: correct Vercel root directory, build success, public HTTP check, and route-level smoke test—not merely a green repository push.
P1Define one canonical product per job. Legacy dashboards should be marked “archive”, “prototype”, or “active” to prevent duplicated fixes and learner confusion.
P2Measure outcomes without weakening local-first privacy: anonymous feature health, task completion, recovery from errors, and opt-in learning evidence—not raw learner content by default.

2. Roadmap: solve the highest-risk problems first

Phase 0
Stabilise

Week 1

Make every entry point dependable

  • Add a release checklist to each deployable app: build, health endpoint, key route, and public-access check.
  • Keep Vercel project roots explicit and remove stale output-directory settings.
  • Retain the WSL cache exclusion so Tracker startup copies source rather than gigabytes of dependency caches.
  • For daily cards, test 320px, 768px, 1024px, and 1440px widths with long translated labels.

Done when: all five local Starter services are ready; deployed services answer their health or key-page checks; no primary action overflows its card.

Phase 1
Learner flow

Weeks 2–3

Reduce uncertainty and accidental loss

  • Introduce a single “Continue my plan” action with a short explanation of why it is next.
  • Make Integrated Skills a searchable multi-select unit picker with an “Apply” action and selected-count summary.
  • Use browser history deliberately: Back returns to the previous screen and preserves task context.
  • Add save-draft feedback, clear offline/service-unavailable states, and a recovery action for voice/PDF failures.

Done when: a learner can start, leave, return, and finish a practice session without losing context.

Phase 2
Teacher loop

Weeks 3–5

Turn activity into teachable evidence

  • Give teachers a review queue: learner, task, evidence type, confidence, correction need, and recommended next step.
  • Add an assignment composer with level/skill/topic filtering, original-content review, and plain-language learner instructions.
  • Separate automated signals from teacher-verified mastery in every progress view.
  • Provide export/import and local backup explanations in learner-friendly language.

Done when: a teacher can prepare one focused lesson, review the evidence, and assign the repair task in under ten minutes.

Phase 3
Accessibility and consistency

Weeks 5–6

Make the system usable at different sizes and abilities

  • Run keyboard-only checks for menus, accordions, dialogs, filters, and “Open practice” controls.
  • Test zoom/reflow at 200% and long English, German, and Persian labels.
  • Use visible focus states, button labels, semantic landmarks, and announced loading/error states.
  • Standardise navigation patterns across English, German, Tracker, Settings, and PDF Studio.

Done when: no essential action relies on mouse-only interaction or horizontal scrolling at 320px/200% zoom.

Phase 4
Learn and scale

Weeks 7–8

Decide with outcome signals

  • Define a small, privacy-safe metric set: task start, task finish, repair completion, return-after-error, and teacher review turnaround.
  • Run five learner and two teacher observation sessions; record friction by task, not by opinion alone.
  • Publish a canonical-app map and archive plan for duplicate prototypes.
  • Choose the next investment from evidence: teacher workflow, speech quality, PDF annotation, or multi-device sync.

Done when: the next quarterly roadmap is based on observed task success and a named product owner for each active app.

The primary “Start today’s practice” action now delegates to Activity 1, using the same saved session, level, topic, and return context as its “Open practice” control. A browser regression verifies the Grammar destination and daily-return parameters.

Language resource PDFs now use the canonical reader

PDF actions created inside English and German learning-resource cards now open Research PDF Studio on port 4332, matching the Notebook handoff and its return-context contract. Regression tests assert both the origin and root path so the retired Tracker proxy cannot silently return.

P0 completed · 29 August 2026

German Integrated Skills now uses a searchable multi-select

The long German CEFR catalogue now starts with a compact drop-down where learners can search and select several levels and skills, review a selected-count summary, and apply the choice. Only the applied level accordions are rendered, and their content remains collapsed until requested.

P0 completed · 29 August 2026

German Daily Practice cards now reflow by usable width

Phase 3 uses a minimum card width and collapses before the fixed navigation rail makes the cards too narrow. Status badges, time labels, and “Übung öffnen” controls are constrained to their card, with a regression test at a narrowed desktop viewport.

P1 completed · 29 August 2026

Daily sidebar section controls now work

English and German daily pages now make their visible section headers accessible accordions. Each header collapses and reopens only its own route links, announces the state with aria-expanded, and is covered by a route-level regression test.

P0 completed · 29 August 2026

Integrated Skills menu links now use live routes

The English Daily shell now delegates to the existing app-shell query route, and the German Daily shell targets its canonical /fertigkeiten page. Both links are protected by route-level regression tests so a visible menu item cannot lead to a dead path.

P0 completed · 29 August 2026

German Grammar navigation now matches the app route contract

The static Grammar screen’s Integrated Skills action now uses /fertigkeiten, matching the app navigation and Daily page. The application-route regression list includes that destination, preventing the old removed alias from returning unnoticed.

P0 completed · 29 August 2026

German Notebook and PDF Reader use the live Studio port

Both German handoff routes now target the shared local PDF Studio contract at 127.0.0.1:4332, instead of the retired port 4322. The redirect default is covered by a unit test and retains deployment overrides.

P0 completed · 29 August 2026

PDF handoffs now include an explicit return path

English and German Notebook handoffs now send the calling app URL and a human-readable return label to PDF Studio. The reader can show a real “Back” action instead of leaving a learner at a dead end after opening cross-app materials.

P1 completed · 29 August 2026

Installation metadata no longer advertises unavailable media

Current English and German PWA metadata now uses bundled SVG app icons, omits optional screenshot placeholders, and precaches only real local assets. This avoids fake image responses from exhausted Git LFS media without requiring a paid service; the English browser regression now verifies the SVG roles and current cache contract.

P1 completed · 29 August 2026

Conversation Studio coach now has an offline-safe avatar

German Conversation Studio replaces the broken Git LFS image reference with a bundled accessible SVG. Ava remains visibly identifiable in clean local builds and free deployments without copying or downloading licensed media.
